# Active profile: one A100 40 GB, one segmented attempt

This profile supersedes the original 720p/241-frame single-call plan.
It is designed to reduce memory use; it has **not been benchmarked with VACE
on an A100**. No GPU inference or model loading was performed during this edit.

## Fixed generation settings

Official `Wan-AI/Wan2.1-VACE-14B-diffusers`, one pinned checkpoint revision,
832x480, 16 fps, **81 model frames per call**, 50 steps, guidance 5,
conditioning scale 1, UniPC flow shift 3, BF16 with FP32 VAE, VAE tiling,
**sequential CPU offload**, seed **2026**, unchanged short lab prompt and no
prompt extension. Model inputs are source video + frozen-pipeline board masks
+ the same artwork reference. No audit mask is used for generation.

Sequential offload moves submodules rather than keeping the entire large
transformer on GPU; it trades speed for memory. The lower resolution and
short calls also reduce activation size. Runtime VRAM peaks are recorded per
invocation; no fixed VRAM requirement or runtime is claimed in advance.
The environment/weights setup is unchanged. Prefer substantial host RAM
(the supplied job requests 128 GB); there is no automatic setting fallback.

Each invocation uses exactly the same model/settings/seed. Input frame 80 of
each model segment is tail padding, formed by repeating that source segment's
last frame as needed for the 4n+1 VAE length. All **81-frame raw outputs are
preserved**. The joined video excludes only the predeclared last padding frame
from each segment: 240/16 = **15.000 seconds**, without accumulated seam delay.
This is a deterministic time-boundary rule, not visual selection of outputs.

No crossfade, optical-flow interpolation, geometric correction or classical
background paste is applied. Joining uses lossless H.264 re-encoding of the
decoded segment prefixes. Appearance/motion discontinuity at the 5 s and
10 s boundaries may occur and must be reported, not hidden by blending.
The model can still retime within each segment; report such mismatches.

## Commands on the cluster

Export **new poster_03 board masks** using Notebook 4 first; the archived
poster_01 masks are invalid for this capture.

After pulling the updated code/conditions, keep your existing `LAB_ROOT`,
`VACE_ENV` and `VACE_WEIGHTS` variables. The same environment and checkpoint
download remain valid; no new libraries are required.

From `code/`, define a NEW argument array. Do not reuse an old array containing
`--num-frames 241`, `--width 1280`, or `--offload model`.

```bash
cd "$LAB_ROOT/code"
VACE_SEGMENT_ARGS=(
  --video "$LAB_ROOT/data/personal/poster_03/clip.mp4"
  --artwork "$LAB_ROOT/data/artwork/ad4.png"
  --masks "$LAB_ROOT/code/outputs/genai/inputs/masks"
  --weights "$VACE_WEIGHTS"
  --seed 2026
  --output "$LAB_ROOT/code/outputs/genai/output.mp4"
)

"$VACE_ENV/bin/python" student_files/vace/segmented_infer.py preflight "${VACE_SEGMENT_ARGS[@]}"
```

Preflight checks the full source, all sampled masks, audit declarations,
segment boundaries, declared settings and selected-frame mapping. It does
not import torch, load weights, create an attempt or generate a video.

In a **single-GPU job**, after preflight succeeds:

```bash
"$VACE_ENV/bin/python" student_files/vace/segmented_infer.py run "${VACE_SEGMENT_ARGS[@]}"
```

The driver invokes one fresh Python process per segment, one at a time.
Each process releases its CUDA allocation on exit. Progress is printed to
the parent console; the detailed Diffusers progress is in each segment's
`console_*.log`. To follow it, use `tail -f <printed-console-log-path>`.

If using the supplied Slurm template, it now calls this driver:

```bash
cd "$LAB_ROOT/code/student_files/vace"
sbatch --account=<your-account> --partition=<your-gpu-partition> submit_slurm.sh
```

The template still needs the documented `VACE_VIDEO`, `VACE_ARTWORK`,
`VACE_MASKS` and `VACE_SEED=2026` environment variables. Use your actual
NUS scheduler/account/partition. Do not invoke with torchrun or run GPU
inference on a login node.

## Outputs, failures and resume

- `outputs/genai/output.mp4`: 832x480, 240 frames at 16 fps, full joined edit;
- `outputs/genai/segmented_attempt/attempt.json`: immutable input/settings
  fingerprint, segment status, source/output mapping and hashes;
- `segmented_attempt/segment_00/raw_video.mp4` (and 01,02): each full raw
  81-frame segment, with console logs and original invocation artefacts;
- each segment's `runs/<id>/`: `raw_output.mp4`, `invocation.json`, full
  environment snapshot, timing, VRAM peaks and failure traceback;
- each segment's `inputs/vace/<id>/`: actual sampled RGB frames, board masks,
  artwork and conditions snapshot;
- `manifests/genai_log.csv`: one row per invocation/segment, including failures
  and unchanged-settings technical retries, with the same seed/settings.

There is no automatic retry, resolution fallback, seed search or best-output
selection. If a segment fails, processing stops and preserves all prior raw
results/logs. For a technical restart after the failed job is stopped:

```bash
"$VACE_ENV/bin/python" student_files/vace/segmented_infer.py run "${VACE_SEGMENT_ARGS[@]}" --resume
```

Resume verifies the source/artwork/mask hashes, conditions, model revision and
settings. It keeps completed segments without regenerating them; a completed
child interrupted before its parent's checkpoint can be recovered only from
its matching successful manifest, output hash and saved CSV row. Each technical
restart is logged, and resume code hashes are retained for provenance.

A killed job may leave `.vace-segments.lock` in the output directory and/or
`genai_log.vace.lock` beside the CSV. Remove a stale lock only after confirming
both parent and child processes have stopped. Never remove raw segments or
change settings to make a different-looking result. If an OOM occurs, retain
the failure log and reassess the execution plan before another attempt.
